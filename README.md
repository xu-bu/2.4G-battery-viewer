# 设备电量查看器

Windows 上读取 2.4G 无线鼠标和键盘电量的小工具。**纯 ctypes 调系统 DLL，零第三方依赖**——
不用 hidapi、不用 pystray、不用 Pillow、不用 pywin32，装了 Python 就能跑。

## ⚠️ 只支持这两台设备

这**不是一个通用工具**。协议是针对这两台具体设备验证/逆向得到的——换成别的鼠标或键盘，
大概率一个字节都读不出来（界面会显示「没有可用的读取方式」）。

| 设备 | VID:PID | 读取方式 |
|---|---|---|
| UGREEN 2.4G 无线鼠标 | `2B89:0043` | 厂商接口 usage page `0xFFB5`，Report ID `0xB5`，请求 `B5 01 00 00 00 00 00 00`，电量取回复第 3 字节 |
| 2.4G 无线键盘（AULA / MARVO / YUNZII / iLovbee 等同 3554:FA09 接收器） | `3554:FA09` | 厂商接口 usage page `0xFF02`，Report ID `0x13`，请求 `13 4A 00 ... 校验和`，电量取回复第 5 字节，第 6 字节是电源状态 |

**你的设备不在这两行里？** 别硬改这个仓库，往下看「用 prompt 做一份你自己的」。

## 使用方法

```bash
python my_devices.py
```

面板里会显示实际读到的设备，默认自动刷新，底部可以改刷新间隔。键盘读不到电量时
不显示键盘卡片，鼠标卡片自动占满面板。

- 只想看一眼：`python my_devices.py --once` —— 打印后退出
- 想摸新设备的协议：`python app.py` —— 完整调试版，可枚举接口、转储 Feature Report、探测 Report ID、手动标定

### 托盘与开机自启

- 双击桌面「电量托盘」，或运行 `pythonw 电量托盘.pyw`（不弹黑窗）
- 托盘里只给**真正读到电量**的设备显示数字图标；键盘读不到就不占位置，鼠标始终显示
- 鼠标悬浮在图标上显示「设备名：电量（更新时间）」
- 右键图标打开简洁面板；左键图标立即刷新一次
- 开机自启已做成「启动」文件夹里的快捷方式，任务管理器 →「启动」里可以看到并启用/禁用

键盘休眠时接收器不会回复电量查询，提示「按一下键盘再刷新」即可。鼠标休眠时同理，
动一下鼠标再刷新。如果键盘已开机、已配对仍然没有回复，说明这台键盘的 2.4G 固件
不在这条协议上上报电量（部分三模键盘只提供低电量指示灯），界面会如实显示读不到。

| 设备 | VID:PID | 说明 |
|---|---|---|

## 三、已验证的协议（直接照抄，不用再逆向）

### 1) UGREEN 2.4G 无线鼠标

- 接口：usage page `0xFFB5`，输入 8 字节 / 输出 8 字节，Report ID `0xB5`，没有 Feature Report。
- 请求（8 字节）：

  ```
  B5 01 00 00 00 00 00 00
  ```

- 回复（示例）：

  ```
  B5 01 01 38 43 07 00 48
        ^^ ^^
        |  电量 = 0x38 = 56%
        0x01 = 有效回复
  ```

- **电量 = 回复第 3 字节（从 0 开始数）**；第 2 字节必须是 `0x01`，否则视为无效回复。
- 回复第 4 字节及之后会随鼠标配置/状态变化，不要拿来猜电量。
- 只发 `0x01` 这一条只读查询；同接口上的 `0x02`/`0x05` 是整块配置读取，工具不碰。

### 2) 2.4G 无线键盘（3554:FA09，AULA 同方案）

- 接口：usage page `0xFF02`，输入 20 字节 / 输出 20 字节，Report ID `0x13`。
- 20 字节帧格式：

  ```
  13 <命令> <子命令> <序号> <15 字节数据> <校验和>
  ```

- **校验和 = 前 19 字节之和的低 8 位。**
- 电量查询（只读）：

  ```
  13 4A 00 00 00 00 00 00 00 00 00 00 00 00 00 00 00 00 00 5D
  ```

- 回复命令回显，最高位偶尔被置 1；校验通过后：
  - **电量 = 回复第 5 字节（1~100）**
  - **电源状态 = 回复第 6 字节**：`0x01` = 电池供电，`0x10` = 插线/充电中
- 插线时接收器把电量固定报 100，所以此时只显示「充电中」，不显示假百分比。
- 键盘休眠 / 没开机 / 没配对时接收器不回复；按一下键盘，等 200ms 再重试。
- **键盘读取只走 2.4G 接收器（3554:FA09 / 0xFF02），不会打开 USB 线（258A:0199）
  上的接口。** 因此只在插线时才存在的字段不会被当成无线电量显示；2.4G 读不到就隐藏。

### 3) 兜底（换设备时用）

优先级：标准 HID 电量字段（Generic Device Controls `0x0006/0x0020` Battery Strength）→
厂商协议表（UGREEN、Endgame `0x3367`、VAXEE `0x3057`、Nordic `0x1915`）→
罗技 HID++ 2.0（特性 `0x1000/0x1004/0x1001`）→ 监听 Input Report →
手动标定（把 Report ID / 电量字节下标 / 倍率存成 JSON）。

## 四、已知的坑（务必规避）

1. **绝对不要在同一 HID 句柄上"阻塞 ReadFile + 并发 WriteFile/IOCTL"** ——
   实测会直接杀掉进程（连 Python 异常栈都没有）。
   正确做法：用独立的、带 `FILE_FLAG_OVERLAPPED` 的读句柄 + 事件超时 + `CancelIoEx`。
2. **系统独占的顶层集合**（鼠标/键盘/笔/触摸屏）只能用 `dwDesiredAccess=0` 打开，
   能读属性和 Feature Report，但不能发指令。本项目的鼠标/键盘电量都走**厂商集合**，
   不碰系统独占的那几个接口。
3. **销毁托盘窗口后必须 `PostQuitMessage(0)`**（在 `WM_DESTROY` 里发）。
   只调 `DestroyWindow` 会留下"窗口没了、图标也没了、但进程还活着"的僵尸进程，
   它还占着单实例锁 → 之后再也启动不起来，而且 `pythonw` 没有控制台，用户看不到任何报错。
4. **Tkinter 不是线程安全的**：后台线程不要直接调 `root.after()`，
   用 `queue.Queue` 把结果交给主线程，主线程用 `after(100, pump)` 取。
5. **托盘图标不要"删了再加"**：`NIM_DELETE` 删掉的图标，用 `NIM_MODIFY` 是改不回来的，
   必须重新 `NIM_ADD`。另外不做 DPI 声明的话图标会被系统缩放得发糊（要 `SetProcessDPIAware`）。
6. **创建 .lnk 用纯 ctypes**：`CoCreateInstance(CLSID_ShellLink)` → `IShellLinkW` →
   `QueryInterface(IPersistFile)` → `Save()`。vtable 下标：
   `SetPath=20 SetArguments=11 SetWorkingDirectory=9 SetDescription=7 SetIconLocation=17`、
   `GetPath=3 GetArguments=10 GetWorkingDirectory=8`；`Load=5 Save=6`。
   GUID 字符串要用 `split("-", 3)` 解析（最后一节里还有连字符）。
7. **别让常驻程序"自动纠正"用户设置**：托盘只应当**读**开机自启的真实状态，
   绝不能因为读到一次不一致就替用户删/建启动项。

## 五、验收标准

1. `python my_devices.py --once` 能打印鼠标 xx%；键盘读到才打印，读不到不打印。
2. 简洁面板里只显示实际读到的设备；鼠标卡片始终显示，键盘读不到时自动隐藏，
   百分比颜色随电量变化（≥60 绿 / 30–59 黄 / <30 红）。
3. 任务管理器 →「启动」标签里能看到「电量托盘」，可直接启用/禁用，
   且与界面里的「开机自启」勾选框状态一致。
4. 桌面上有「电量托盘」快捷方式，双击不弹黑窗；托盘图标只给读到的设备显示。
5. 项目目录里**不产生任何日志文件**；`--debug` 时才有控制台输出。
6. 连续启停托盘 3 次正常；退出后无残留进程、无残留托盘图标。
7. 空闲时 CPU 占用接近 0（实测 75 秒内 < 0.5 秒 CPU）。

## 两个值得一提的实现细节

1. **同一 HID 句柄上并发「阻塞读 + 写」会直接杀掉进程**（连异常栈都没有）。
   正确做法是独立的 `FILE_FLAG_OVERLAPPED` 读句柄 + 事件超时 + `CancelIoEx`。
2. **销毁托盘窗口后必须 `PostQuitMessage(0)`**。只调 `DestroyWindow` 会留下
   「窗口和图标都没了、但进程还活着」的僵尸进程，它占着单实例锁，导致之后再启动都没反应。

## 隐私

- **不联网**：没有任何 http / socket / urllib / 遥测调用，所有读取都在本地 HID 层完成。
- **不写日志**：默认不产生任何日志文件；只有 `--debug` 时才往控制台打印。
- **不上传**：设备序列号、地址等信息只在内存里用，不落盘。
